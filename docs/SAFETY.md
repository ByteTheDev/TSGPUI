# Safety and trust model

- This project never edits existing application installations or executables; packaging **copies** a host to an output directory before appending the bundle.
- No cleanup tools, disk wipes, uninstallers, system registry edits, elevation requests, or background services are included.
- The development command watches only project files and restarts only the host process it spawned.
- The native binary must be trusted: use a local source build or a checksum-verified CI artifact.
- Importing an Electron project runs project code. `tsgpui import electron --build` runs the source project's `build` script, and `tsgpui run` and `tsgpui build` run it when no built renderer exists. The script runs with your user's rights. Conversion writes to a new directory and leaves the source unchanged, but it does not sandbox the script. Import only Electron projects you trust.
- Cross-target packaging copies a verified prebuilt host for another platform and appends the bundle. It does not run that host. `tsgpui package --sign` runs the command in `TSGPUI_SIGN_COMMAND` on each artifact; see the [release guide](RELEASING.md).
- The QuickJS backend has no ambient filesystem, process or network APIs. Its only host access is `api.native`, and the host checks each call against the bundle's `permissions`: filesystem paths stay inside granted roots (symlinks included), only listed executables run, without a shell, and window, notification and IPC calls need their own grants. HTTPS requests reach only hosts listed in `permissions.network`. Clipboard, dialog and external-link calls need no grant, as in the WebView renderer, but each dialog-picked file is granted only for that one file for the rest of the run. Host calls run on background threads. Each backend load, action, or state write has a 2-second wall-clock limit and a 32 MiB heap limit, and time spent waiting on a host call does not count against it. An action that exceeds the limit is aborted and its state is rolled back. Limits do not cover memory used outside the JS heap, so still do not execute untrusted backend code.
- IPC listens on `127.0.0.1` with a random token. Any process running as the same user can read the token from a child process's environment or from the app's memory, so IPC is for coordinating your own processes, not a security boundary against local malware. A peer that sends the wrong token is disconnected before any message is read.
- `tsgpui preview` serves host operations to its own page only. Each request needs a random token that only the page receives, and the exact `Host` header of the preview server, so another website, or a DNS name rebound to `127.0.0.1`, cannot call them. Preview calls still run with your user's rights, limited by the same grants.
- The WebView renderer runs authored page scripts and the compiled backend in the system browser engine. It is not a sandbox: those scripts can use browser APIs and make network requests outside `permissions.network`. Only package HTML, CSS, scripts, and backends you trust.
- CLI `init` refuses to overwrite a nonempty project folder. The CLI resolves symlinks for the config, HTML, CSS, backend, image and font assets, WebView resources, and output directory, and rejects any that point outside the project. It also refuses to write through a symlink at the output path. The check runs once at build time, so a project edited concurrently could still race it; do not build untrusted projects.
- `tsgpui preview` runs the backend in a browser page, not in QuickJS, so its limits are the browser's, not the host's. The page's content security policy allows script from the page itself (the preview needs `unsafe-eval` to run the backend), and limits connections through `connect-src` to the preview origin and configured HTTPS hosts. Other request types are governed separately by the policy. The preview server listens on 127.0.0.1 only, and it serves only the page and a version number. Do not treat a preview as a sandbox for untrusted backend code.
- Appending an overlay invalidates any existing signature. Use an unsigned prebuilt host, package it, then sign the finished Windows executable or macOS `.app`. macOS distribution also requires the app to be notarized for a smooth Gatekeeper experience.
- The release packaging replaces the **generated output file** when rebuilt; keep backups of outputs you need to retain. It never targets existing installed apps.
- Dependencies, gpui versions and GitHub Actions permissions should be audited/pinned before public releases.

## WebView content and grants

WebView HTML, authored scripts and the compiled backend run together in the browser engine and must be trusted. Page scripts can call `window.tsgpui.invoke`; host operations are checked against the bundle's filesystem, process, notification, IPC and window grants. Those grants do not isolate scripts from each other or prevent access to browser APIs. The backend's shadowed API names are not a security boundary.

The generated page's CSP defaults to denying resource types. Scripts from the page origin and script elements bearing a fresh build nonce are allowed; inline event-handler attributes are blocked. `unsafe-eval` remains necessary because the backend bootstrap executes its source with `new Function`; removing it requires a different backend execution strategy. Inline styles remain allowed because generated and authored styles and style attributes are embedded in the page. Images, fonts and media allow the page origin and data URLs; connections allow the page origin and configured HTTPS network hosts; forms, frames and base URLs are restricted to the page origin, and objects are denied. The nonce authorizes authored script elements, not untrusted content, and the policy is defense in depth, not a sandbox. Navigation and browser behavior outside these directives are not governed by `connect-src`. CSP also cannot replace host-side permission checks.

Before this policy change, `default-src 'self'` supplied a same-origin fallback; `script-src 'self' 'unsafe-inline' 'unsafe-eval'` allowed local and arbitrary inline scripts and dynamic compilation; `style-src 'self' 'unsafe-inline'` allowed local and embedded styles; `img-src`, `font-src`, and `media-src` allowed same-origin and data resources; `connect-src` allowed same-origin and the configured HTTPS hosts; `object-src 'none'` blocked plugins; and `base-uri 'self'` restricted base URLs. Forms and frames had no dedicated restriction. The fallback was broader than the generated bootstrap needs; the explicit resource directives remain for application content. The generated CSS and existing inline style attributes require inline styles, and the backend bootstrap requires dynamic compilation.

Electron preload scripts run in the same WebView JavaScript world as renderer scripts, before renderer scripts. A facade scopes ordinary window and globalThis property assignments to the preload, but it is not an Electron isolated world or a security boundary: shared browser objects, DOM access, indirect access to the real window, and other APIs remain available, and preloads must be trusted. contextBridge rejects existing global names and copies and freezes exposed plain objects and arrays, but exposed functions still execute in the shared world and are not a security boundary.
