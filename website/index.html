import type { AppDefinition } from "tsgpui/types";

type CounterState = { count: number };

// Runs in QuickJS inside the native GPUI process, not in a browser.
const app: AppDefinition<CounterState> = {
  state: { count: 0 },
  actions: {
    increment(api) {
      api.set("count", api.get("count") + 1);
    },
    decrement(api) {
      api.set("count", api.get("count") - 1);
    },
    reset(api) {
      api.set("count", 0);
    }
  }
};

export default app;

How it works

Three parts, each with one job.

Markup is compiled ahead of time, logic runs in a small sandbox, and the pixels come from a native GPUI host. Nothing in the shipped app asks for a browser or a JavaScript runtime.

Markup and styles

A strict subset of HTML and CSS is parsed at build time into an element tree with explicit keys. CSS selectors, specificity and inheritance are resolved before anything reaches the window, so the layout you write is the layout that ships.

TypeScript backend

One backend.ts exports state and actions. It is transpiled to JavaScript and run in embedded QuickJS on the UI thread. Actions are synchronous and see only get, set and update.

One executable

Packaging copies a prebuilt GPUI host and appends the app bundle to it. The result is a single .exe that runs without Bun, Node or Rust on the machine.

Compilation pipeline

From source files to one native executable.

Each stage writes a file you can inspect. The bundle is plain JSON, so you can open it and see exactly what the host will render.

Copies the prebuilt host and appends the bundle, then the host reads it back at startup.

Architecture

Native rendering with a small, contained backend.

The design trades browser breadth for a smaller, inspectable system. These are the properties the current prototype is built around.

  1. Parse

    Strict HTML subset to an element tree with explicit keys and attributes. Unsupported tags fail the build.

  2. Style

    CSS parsed with PostCSS. Descendant matching, class and id selectors, inheritance and specificity are resolved.

  3. Transpile

    The single backend file is compiled with the TypeScript compiler to CommonJS (ES2020).

  4. Render

    The GPUI host opens a GPU-accelerated window and draws the tree. Media queries are evaluated at compile time.

  5. Run

    Clicks invoke actions in QuickJS. The view takes a state snapshot and redraws. QuickJS has an approximate heap cap, not a CPU-time limit.

No browser engine

No Chromium and no WebView in the runtime path. Rendering goes through GPUI.

No Node or Bun at runtime

Bun or Node is needed for development. The distributed app does not need either one installed.

Fast iteration

Changing HTML, CSS or TypeScript recompiles the bundle and reuses the existing host. Rust is not rebuilt.

Plain-text bundle

The .tgp document is JSON. Its format and contents can be read and checked directly.

Compile-time components

<template data-component> is expanded at compile time. Recursive uses and duplicate IDs are rejected.

Explicit data binding

data-bind and {{stateKey}} read backend state. data-onclick dispatches named actions.

Quick start

Build the counter from a checkout.

Requires Bun or Node 20+ for the developer CLI. Compiling the bundle does not need Rust. Building the native host does.

1. Check and compile the example

bun install
bun run test
bun run gpui:compile

Writes examples/counter/dist/tsgpui-counter.tgp.

2. Get a native host, once per machine

Either point TSGPUI_HOST at a host you trust, or compile one with the Rust toolchain. On Windows that also needs the MSVC build tools. 

bun run gpui:host

3. Package the executable

bun run gpui

Writes examples/counter/dist/tsgpui-counter.exe.

Or start a new project with the CLI

tsgpui init my-app
cd my-app
tsgpui dev

tsgpui dev rebuilds and restarts the host on save. It is a fast reload, not state-preserving hot module replacement. tsgpui build writes the single executable.

Read the full docs, the CLI reference and the repository.

Status

An experimental prototype, stated plainly.

TSGPUI is not a production-ready GUI SDK. The supported subset is small on purpose, and the list below is what the project currently documents.

Works today

  • Strict HTML subset with class, id, data-bind and data-onclick
  • CSS with element, class, id and compound selectors, specificity and inheritance
  • Flex and grid layout, px sizing, hex colours and bold weights
  • Synchronous backend actions with get, set and update
  • Compile-time <template> components
  • Single-executable packaging with the appended bundle

Not yet

  • Forms, text input and keyboard handling
  • Images and dynamic data lists
  • Media queries that respond to window resizing
  • Exact mixed fr and px grid sizing
  • Dialogs, clipboard, file access and network requests
  • Hard CPU-time limits, or isolation for untrusted backend code
  • Signed, encrypted or tamper-proof packages

Only run backend code you trust. The container format is a prototype, and the Windows host is still being validated through CI.
